# 코인 급등 분석기 V16

[프로젝트 안내로 돌아가기](../README.md)

모든 명령은 프로젝트 루트인 `C:\dev\Coin_api`에서 실행합니다. 분석 코드는 `coin_analysis/`, DB는 `data/`, 결과는 `reports/`, 테스트는 `tests/`에 있습니다.

업비트 원화 마켓을 대상으로 하는 연구용 분석기입니다. 현재 작업에서는 V15를 사용하지 않으며, 기존 파일과 데이터베이스는 비교용으로 보관합니다. 실제 주문은 전송하지 않습니다.

## 현재 진행 방향: 오프라인 검증 우선

과거 데이터 분석으로 가설의 유효성을 확인하기 전까지 실시간 검사는 보류합니다.

### 실제 급등 사례의 공통점 분석

```powershell
python -m coin_analysis.surge_pattern_lab
python -m unittest tests.test_surge_pattern_lab -v
```

V16의 진입 조건을 적용하지 않고 독립적으로 분석합니다. 6시간·24시간·72시간 안에 +20%·+50%·+100% 상승한 사건을 사후에 추출하고, 그 이전의 가격·이평선·거래대금 특징을 확인합니다. 같은 종목에서 시기가 가깝고 이전 거래대금이 비슷했던 비급등 구간을 대조군으로 비교합니다.

결과는 `reports/surge_pattern_result.md` 보고서와 `reports/surge_pattern_result.json` 상세 데이터에 저장됩니다.

데이터가 있는 경우 사건의 기준 시점과 그보다 5분·15분·60분·360분 전의 특징을 기록합니다. 기준 시점은 사후 분석을 위한 기준점이며, 실제 급등 시작 시점으로 확인된 것은 아닙니다.

동일한 사건 정의 안에서는 사건별 미래 평가 구간이 겹치지 않도록 처리합니다. 다만 기간이나 상승률 기준이 다르면 같은 상승 구간이 중복으로 포함될 수 있습니다. 데이터가 부족하면 대조군을 찾지 못할 수 있으며, 사건 수와 매칭되지 않은 건수를 명시합니다.

적은 표본만으로 예측에 유용한 공통점이라고 판단하지 않습니다. 이미 결과를 확인한 후반부 기간도 새로운 미사용 검증 데이터로 간주하지 않습니다.

### V16의 1분봉 근사 모델 백테스트

```powershell
python -m coin_analysis.backtest_v16
python -m unittest tests.test_backtest_v16 -v
```

`data/historical_market.db`를 읽기 전용으로 사용하며 네트워크 요청은 하지 않습니다. 결과는 `reports/backtest_v16_result.md` 보고서와 `reports/backtest_v16_result.json` 상세 데이터에 저장됩니다.

이 백테스트는 1분봉 거래대금을 사용합니다. 실시간 분석기의 30초 거래량 및 체결 건수 조건은 재현하지 않습니다. 분당 거래대금 6천만 원 기준은 별도의 근사 가설이며, 실시간 조건을 동일하게 환산한 값이 아닙니다.

봉이 마감된 시점에 신호를 판단하고, 다음 봉 시가에 가상 진입한 것으로 계산합니다. 왕복 비용은 기본 0.20%로 가정하며 `--cost-pct`로 변경할 수 있습니다.

이후 데이터가 연속으로 존재하는 경우 30분·1시간·6시간·24시간·72시간 후 결과를 평가합니다. 데이터가 빠진 구간은 제외하고 제외 건수를 표시합니다.

모든 종목에 동일한 시간 기준으로 전반 70%와 후반 30%를 적용합니다. 이 구분만으로 전략의 유효성을 입증할 수는 없으며, 이미 관측한 후반 30%는 새로운 미사용 검증 구간이 아닙니다.

## 실시간 실행: 현재 보류

```powershell
python -m pip install -r requirements.txt
python -m coin_analysis.scanner_v16 --markets KRW-BTC KRW-ETH
python -m coin_analysis.scanner_v16
python -m unittest tests.test_scanner_v16 -v
```

`--markets` 옵션 없이 실행하면 현재 상장된 업비트 원화 종목 전체를 감시합니다. `--markets KRW-BTC KRW-ETH`를 지정하면 두 종목만 감시합니다. 종료하려면 `Ctrl+C`를 누릅니다.

`--duration 30`은 실행 시간을 30초로 제한하는 연결 확인용 옵션입니다. 신호 발생에 필요한 관측 시간을 충족하지 못합니다. 별도의 `data/scanner_v16.db`에 관측 기록을 저장합니다.

## 실시간 탐지의 초기 가설

- 완성된 5분봉 기준 SMA20의 3개 봉 전 대비 변화율이 -0.10% 이상
- 현재 가격이 SMA20 이상이고, 이평선보다 높은 정도가 3% 이내
- 최근 5분 가격 변화율이 0% 이상 3% 이하
- 최근 30초 거래대금과 코인 거래 수량이 각각 기준값의 3배 이상
- 기준값은 직전 10개의 30초 구간에서 계산한 평균과 중앙값 중 큰 값
- 최근 30초 거래대금 3천만 원 이상, 체결 20건 이상
- 거래가 들어오는 종목별로 5초 간격 평가, 알림 후 30분 동안 재알림 제한

조정 가능한 옵션은 `--min-value`, `--value-ratio`, `--volume-ratio`, `--markets`, `--db`입니다.

이 기준들은 아직 검증되지 않은 연구용 설정이며 수익 예측이 아닙니다. 여기서 SMA20은 5분봉 20개의 단순이동평균으로, 100분에 해당합니다. `FLAT`은 이평선 변화율이 ±0.10% 이내인 상태를 뜻합니다.

## 데이터 처리와 한계

연결할 때마다 최소 330초, 즉 5분 30초 동안 실시간 데이터를 모아야 합니다. 재접속하면 과거 봉을 다시 불러오고 실시간 비교 구간을 초기화합니다. 미리 불러온 봉이 오래되어 연결 시점과의 사이에 누락 구간이 생기면 해당 이력을 버리고, 완성된 봉 23개를 다시 모아야 합니다.

시간 순서가 뒤바뀐 체결은 제외하고, 보관 중인 구간 안에서 같은 식별자의 체결이 반복되면 무시합니다. 이 처리로 실제 거래량보다 적게 집계될 수 있습니다.

실시간 처리에서 거래가 없는 5분 구간은 마지막 종가를 유지합니다. 다음 봉의 첫 가격을 반영하기 전에 이전 체결 가격으로 기존 봉을 마감합니다. 과거 가격과 실시간 거래 수량을 혼합해 거래량 기준값을 만들지 않습니다.

실시간 DB의 `events`에는 신호의 특징과 설정을 저장합니다. `observations`에는 신호 이후 최대 72시간 동안 약 1분 간격으로 관측 가능한 가격을 저장하며, 재시작하면 추적을 이어갑니다. 실제 관측 시각을 유지하고 연결 중단 중의 가격은 임의로 채우지 않습니다.

이 관측값은 정확한 고가·저가나 정해진 시점의 가격을 보장하지 않으며, 가상매매 결과도 아닙니다. 체결이나 수수료를 계산한 결과로 해석해서는 안 됩니다. 가격을 관측하려면 새 체결이 들어와야 하며, 알림은 터미널 출력으로만 제공합니다.

현재 버전은 업비트만 지원하며 V15의 빗썸 연결은 포함하지 않습니다. 놓친 급등의 비율 측정, 모든 탈락 후보의 기록, 수익성 검증은 아직 완료하지 않았습니다.
