## 구현

- `/` 실시간 감시, `/analysis` 급등 신호 분석의 두 메뉴만 제공한다. 기존 다크 테마를 유지하고 녹색·적색 수치, 카드, SVG 차트, 반응형 CSS, 빈 상태를 추가했다. JSON·로그·경로를 기본 화면에 노출하지 않는다. 기존 점수 미정의와 실제 저장 패턴을 유지한다.
- BAT 기본은 웹만 열기다. 웹 시작은 기존 V4.10 관리 프로세스와 V4.3 관측 엔진을 실행하고 기존 모든 시계 검증·잠금·상한을 유지한다. 실제 manager/worker 생성 시각과 OBSERVING을 확인한다. 웹 종료는 기존 scoped STOP과 정상 저장 확인만 수행하며 웹을 유지한다. BAT 종료는 웹도 종료한다.
- 중복 시작을 차단한다. 시작 준비 중 종료와 지연된 프로세스 부팅도 별도 취소 표식으로 차단한다. 프로세스 이름으로 일괄 종료하거나 다른 Python을 종료하지 않는다.
- 제어는 `127.0.0.1`에만 바인딩한다. Host·정확한 Origin·Fetch-Metadata·서버 수명별 토큰·별도 인증 헤더·고정 JSON POST를 검증한다. CORS를 허용하지 않으며 CSP와 프레임 차단을 유지한다. 브라우저에서 실행 한도·전략·주문을 변경할 수 없다.
- 분석은 기존 `v42.record_metrics`를 작은 메모리 복제본에 재사용한다. 원천 DB는 읽기 전용이며 파생 평가만 별도 `analysis.db`에 저장한다. 기존 COMPLETE는 재사용하고 미완성 평가는 웹 재시작·주기 갱신 후 실제 저장 데이터로 재평가한다. 새 가격 다운로드는 없다.
- 연구 보관/신규 관측과 LIVE/CATCHUP을 구분한다. 전체 조회 범위로 통계를 계산하고 목록만 200개씩 나눈다. 기존 카탈로그의 최근 32개 관측 저장소 경계를 유지한다.

탐지 규칙·임계값·feature·label·5분 관측 주기·결측 정책·시계 기준은 변경하지 않았다. 기존 평가의 기준은 `signal_time`/`signal_price`이며 실제 탐지 시각과 구별한다. 탐지 지연이 있는 자료를 탐지 이후 거래 성과로 해석하지 않는다. 통계 MFE/MAE는 30분 구간으로 통일하고 각 표본 수를 명시했다. 개별 상세는 기존처럼 가장 긴 완료 구간을 함께 표시한다.

## 실제 제한 시작·종료

사전에 최대 2회, 회당 120초/80 HTTP, UPBIT·BITHUMB의 기존 BTC/ENA/ETH/FLOCK/SAND 범위, 총 NTP 최대 48시도를 고정했다. **실제 시작은 1회만 요청했다.**

실제 loopback POST는 202, 바로 이어진 중복 시작은 409, 외부 Origin·잘못된 토큰은 403이었다. 실제 PRECHECK 프로세스 생성 후 `CLOCK_REFERENCE_OFFSET_OR_UNCERTAINTY`로 BLOCKED됐다. Windows 시간 서비스 조회도 0x80070426으로 실패했다. NTP 7시도 중 6개 유효 응답과 1 timeout을 기록했고, 측정 offset은 약 +1.44~+1.45초였다. 기존 1초 기준을 통과하지 못했다. 설정 변경·우회·추가 재시도는 하지 않았다.

worker·관측 DB 생성·거래소 HTTP·신규 신호는 모두 0이다. 종료 요청 후 소유 Scanner 프로세스가 없고 `/analysis`는 계속 200임을 확인했다. 최종 소스에서는 시작 전 차단으로 관측 DB가 없는 상태의 종료를 '실행 중인 스캐너 없음'으로 구분하며 SAVED라고 주장하지 않는다. 기존 시계 실패 이력은 그대로 보존한다.

최초 웹 시작은 초기 분석을 준비하는 동안 8초 readiness 상한에 도달해 안전 중단됐다. 분석 준비를 백그라운드로 분리한 뒤 BAT로 웹 시작·종료·재시작을 확인했다. 재시작은 스캐너를 자동 실행하지 않았다. 서버 재시작 후 이전 토큰 거부, 분석 재개, 원본 215개와 30분 유효 174개 복원을 확인했다.

## 보존과 한계
