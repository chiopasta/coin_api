# 급등 이벤트 연구 V2

## 중간 규모 검증 상태

전체 실행 전에 [40종목 진단 보고서](../reports/surge_event_v2_medium_audit.md)와 [대표 10개 가격 차트](../reports/surge_event_v2_medium_charts.html)를 확인하세요.

API 없이 DB 일별 관측 개수로 선정한 KST 2026-08-19~08-24의 5일 구간에서 A 43건, B 10건, 고유 episode 37개를 확인했습니다. 주 대조군 A 5/43, B 0/10, 보조 대조군 A 9/43, B 0/10입니다. 조건은 완화하지 않았습니다. 진단은 다음 명령으로 재현할 수 있으며 이벤트 분석 대상은 40종목으로 제한됩니다.

```powershell
python -m coin_analysis.surge_event_audit_v2
```

발견한 제한:

- 53사건 중 42사건은 사건 자체의 과거 기준 유동성 창에 누락 분봉이 있어 매칭을 시작하지 못했습니다. 유동성 배율 초과와 다른 문제입니다.
- ONG 1건에서 episode 재시작 시 저점 큐 초기화 때문에 저장된 t0가 전체 과거 시간 창 최저 종가 시각과 달랐습니다. 현재 구현은 재시작 이후 구간의 최저 종가를 사용할 수 있습니다. 정의와 구현 중 어느 쪽을 기준으로 삼을지 결정하기 전 전체 결론용 실행을 보류하는 것이 좋습니다. 이번 검증에서는 이 동작을 바꾸지 않았습니다.
- 5개 episode에서 A가 여러 건입니다. B의 긴 평가 구간이 여러 A 사건을 연결합니다. event 통계와 episode·유형별 첫 event 통계를 audit JSON에 구분해 두었습니다. 같은 episode의 여러 A를 독립 상승 흐름으로 해석하지 마세요.
- 53사건 중 미래 창에 일부 누락이 있는 사건은 23건, 최초 도달 이전에 누락이 있는 사건은 17건입니다. 사전 특징과 대조군의 완전 관측 조건과 비대칭이며, 분석 표본 편향을 점검해야 합니다.
- 대표 10개 × 5개 시점의 거래대금 배율은 37/50개 NULL입니다. 적은 유효 표본으로 공통점이나 예측력을 주장할 수 없습니다.

확인한 원본 DB 해시는 실행 전후 동일하고, 기존 8종목 대조군 ID도 진단 전후 동일합니다. 실제 데이터 스냅샷 50개에서 미래 제거 불변성을 확인했습니다. 기존 미래 변경 테스트도 유지합니다.

## 범위와 실행

기존 SQLite DB를 `mode=ro`, `PRAGMA query_only=ON`으로 읽습니다. 네트워크 모듈, API 호출, 다운로드 경로가 없습니다. 원본 DB에 테이블을 만들지 않습니다. 기존 V1과 기존 분석 결과도 변경하지 않습니다.

전체 저장 종목 분석 명령:

```powershell
python -m coin_analysis.surge_event_research_v2 --db data/altcoin_market.db --btc-db data/historical_market.db --output reports/surge_event_research_v2
```

`--markets`를 생략하면 DB에 저장된 모든 종목을 분석합니다. 현재 원본에는 280종목이 있습니다. 별도 시가총액 또는 스테이블코인 필터는 적용하지 않습니다. `--btc-db`를 생략하거나 BTC 데이터가 해당 시각에 없으면 BTC 상대강도는 NULL입니다. 기본 기간은 선택 종목의 실제 저장 범위입니다. 과거 360분 준비 구간도 가능한 범위에서 읽습니다. 미래 평가 창이 종료 시각을 넘는 사건은 추출하지 않습니다.

소규모 검증 실행:

```powershell
python -m coin_analysis.surge_event_research_v2 --markets IOST SOPH ONDO SUI SHIB TRUMP XLM ZORA --start 2026-09-08T00:00:00+09:00 --end 2026-09-11T00:00:00+09:00 --btc-db data/historical_market.db --output reports/surge_event_research_v2_smoke
```

시각에 시간대가 없으면 UTC입니다. 끝 시각은 미완성 봉을 배제하는 경계이며 해당 시각까지 완성된 봉을 사용합니다.

## 사건과 t0

- A: 60분 내 과거 기준 종가 대비 이후 고가 +10% 이상.
- B: 360분 내 과거 기준 종가 대비 이후 고가 +20% 이상.
- 시간순으로 각 봉의 고가를 보면서 실제 timestamp 기준 과거 H분 안의 최저 **완성 종가**와 비교합니다. 처음 기준을 만족한 봉을 관측된 최초 목표 도달 봉으로 기록합니다.
- t0는 그 기준 종가의 확정 시각입니다. 최저 종가가 같으면 가장 최근 시각을 선택합니다. 봉의 low를 기준 가격으로 사용하지 않습니다.
- 가격만으로 사건을 선정합니다. MA, 거래대금, 돌파, 사전 유동성은 사건 선정 조건이 아닙니다.
- t0는 미래 목표 도달을 확인한 뒤 지정한 사후 기준점입니다. 실제 상승 시작의 유일한 정답이나 실시간 탐지 가능 시각이 아닙니다.
- 고가의 초 단위 도달 시각은 알 수 없어 목표 도달 봉 시작/종료 시각과 소요시간 하한/상한을 저장합니다. 최고가는 t0부터 H분까지 관측한 전체 미래 창에서 계산합니다.
- 기본적으로 미래 H분의 봉 관측률 80% 이상을 요구합니다. 없는 봉은 채우지 않으며, 부분 관측 사건의 최초 도달/최고가는 관측 기준입니다. `--min-event-coverage 1`로 완전 관측 사건만 추출할 수 있습니다.
- 이벤트는 특징 결측이나 대조군 미매칭 때문에 제거하지 않습니다.

## 중복 제거

같은 종목·같은 유형은 사건의 미래 창이 끝나고, 고점 이후 종가가 고점 대비 최소 5% 되돌린 뒤에만 새 사건을 허용합니다. 이후 최고가가 더 높아지면 고점을 갱신합니다. 되돌림 봉 내부 고가/저가의 순서를 추정하지 않습니다. 잠금 해제 시 이전 기준 저점을 재사용하지 않습니다.

5%는 상승 흐름을 구분하기 위한 고정 연구 규약이며 매수 조건이 아닙니다. 강한 지속 상승에서는 재시작 사건을 보수적으로 줄일 수 있습니다. A/B는 각각 분석하고 시간 구간이 겹치는 사건은 같은 `episode_id`로 묶습니다. A+B 사건 수를 독립 사건 수처럼 합산하지 않습니다.

## 특징 정의

스냅샷은 t0 이전 5·15·30·60·120분입니다. 각 계산은 해당 시각까지 마감된 봉만 사용합니다.

| 특징 | 정의 |
|---|---|
| 5/15/30/60분 수익률 | 정확한 스냅샷 종가 / 정확한 과거 시각 종가 − 1 |
| 최근 거래대금 | 최근 5분 trade_value 합계 |
| 거래대금 배율 | 최근 5분 합계 / 그 이전 60분 합계의 1/12 |
| 거래대금 증가율 | 최근 5분 / 직전 5분 − 1 |
| 거래대금 가속 | (최근 5분 / 직전 5분) / (직전 5분 / 그 이전 5분) |
| MA5/MA20 | 1분봉 종가의 5분/20분 산술평균 |
| MA 기울기 | 현재 MA20 / 5분 전 MA20 − 1 |
| 최근 고저폭 | 최근 30분 최고가 / 최저가 − 1 |
| 변동폭 증가율 | 최근 30분 고저폭 / 이전 30분 고저폭 − 1 |
| 직전 고점 | 현재 봉을 제외한 직전 60분 최고가 |
| 고점까지 거리 | 직전 고점 / 현재 종가 − 1; 돌파 시 음수 |
| 돌파 | 현재 종가 > 직전 고점 |
| 알트 상대강도 | 자기 60분 수익률 − 타 선택 종목 60분 수익률 중앙값 |
| BTC 상대강도 | 자기 60분 수익률 − 별도 DB의 BTC 60분 수익률 |

MA·거래대금·고저폭 등 집계는 창 안의 분봉이 모두 있어야 계산합니다. 수익률은 정확한 양 끝 종가가 있어야 합니다. 분모가 0이거나 입력이 부족하면 NULL입니다. 과거 봉 개수로 시간 길이를 대신하지 않습니다. 시장 중앙값에는 수익률이 존재하는 타 종목이 최소 3개 필요하며 스냅샷마다 종목 수를 기록합니다. 소규모 테스트의 상대강도는 해당 부분집합 기준입니다. 과거 상장 목록을 복원한 지수는 아닙니다.

현재 DB에는 정확한 코인 거래수량이 없어 모든 관련 항목을 거래대금으로 표시합니다.

## 대조군

주 대조군은 같은 시각의 다른 선택 종목입니다. 보조 대조군은 같은 종목의 전후 7일 이내, 정시 간격으로 생성한 다른 시각 후보입니다. 둘을 독립적으로 보고합니다.

매칭 규칙:

1. 기준 유동성은 t0−360분부터 t0−240분까지의 분당 평균 거래대금. 연구할 단기 증가 특징을 매칭으로 제거하지 않도록 더 앞선 구간을 사용합니다.
2. 사건 유동성의 1/3~3배 범위. 비율 차이와 시간 차이가 작은 후보를 우선하며 동률은 종목·시각 순으로 결정합니다.
3. 대조군은 과거 360분과 해당 미래 H분 모두 완전한 분봉 데이터가 필요합니다.
4. 기준 종가 이후 목표 상승이 없어야 하며, 미래 창 안에서 하락 후 다시 급등한 후보도 제외합니다.
5. 알려진 같은 유형 사건과 미래 구간이 겹치는 후보를 제외합니다.
6. 대조 분석별 같은 유형·종목의 겹치는 미래 구간을 재사용하지 않습니다. 사건당 주·보조 대조군 각각 최대 1개입니다.

대조군의 완전 관측 기준은 결측을 비급등으로 오인하지 않기 위한 보수적 선택이며 유동적인 종목에 편향될 수 있습니다. 사건 유동성 부족, 대조군 부재는 미매칭 사유로 JSON에 남깁니다. 작은 종목 집합에서 주 대조군이 0건일 수도 있습니다. 이를 0% 발생률로 표시하지 않습니다.

## 출력과 해석

JSON에는 실행 설정, DB 경로, 기간, 종목, 데이터 품질, 사건 ID, episode ID, 시각, 가격, 상승률, 스냅샷, 매칭 대조군, 미매칭 사유 및 단일 특징 통계를 저장합니다. Markdown에는 사건 수와 주/보조 대조군별 비교 표를 만듭니다.

비교 표는 양쪽 특징이 모두 존재하는 매칭 쌍만 사용합니다. 급등군 표본수/대조군 표본수, 양성 개수, 발생률, 차이(%p), 제외된 결측 쌍 수를 기록합니다. 사건 전체의 특징은 미매칭 여부와 관계없이 JSON에 남습니다.

이 값은 **P(특징 | 급등군/대조군)**입니다. **P(급등 | 특징)**으로 해석하지 않습니다. 표본 수가 적은 100% 같은 값도 예측력 증거가 아닙니다. 이번 버전은 유의성 검정이나 최종 매수 신호를 만들지 않습니다.

후속 조건부 확률 단계에서는 같은 특징 스키마로 전체 적격 관측의 `market, asof_ts, values, flags, future_label, quality`를 별도 생성해야 합니다. 현재 선택된 사건·대조 표본을 그대로 확률의 분모로 쓰면 안 됩니다. 조건 탐색과 별도 기간 검증도 분리해야 합니다.

## 검증

합성 데이터에서는 미래 변경/잘라내기 불변성, 결측 시각, 현재 봉을 제외한 돌파, 가격만으로 사건 선정, 중첩 A/B 사건, 되돌림 중복 제거, 불완전 미래, 주/보조 대조군, DB 읽기 전용, 원본 해시 불변성과 유효 매칭 쌍 분모를 검증합니다.

실제 데이터 소규모 검증은 위 8종목, KST 2026-09-08~09-11의 3일 범위입니다. 기존 보고서에서 사례가 있는 종목을 포함한 동작 확인 표본이며 시장 전체 성과 검증이 아닙니다. 결과와 매칭 부족은 smoke 보고서에 그대로 공개합니다. 전체 280종목 분석은 자동 실행하지 않았습니다.
