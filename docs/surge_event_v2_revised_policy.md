# V2 수정 연구 정책

이전 V2와 중간 검증 출력은 비교 기준으로 보존합니다. 수정 연구 엔진은 `coin_analysis/surge_event_research_v2_revised.py`이며, 기존 모듈의 읽기 전용 로더와 특징 계산만 재사용합니다. 기존 V2 명령은 과거 기준 재현용입니다.

## 이번 재검증 명령

```powershell
python -m coin_analysis.surge_event_research_v2_revised --min-valid 20
```

이 명령은 저장된 중간 검증 manifest의 정확히 같은 40종목과 KST 2026-08-19 00:00~08-24 00:00만 사용합니다. 기간이나 종목 수가 다르면 중단합니다. coverage 0.80과 1.00 두 정책을 각각 실행합니다. 표본 재선정, 전체 280종목 이벤트 분석, 네트워크 호출은 없습니다.

## 확정한 시간·t0 규약

- `target_time`: 목표 도달 고가를 관측한 1분봉의 **마감/확인 시각**. 실제 체결 시각은 알 수 없으며 `[target_time-60초,target_time]` 안에 있습니다. 봉 시작 시각도 별도 저장합니다.
- t0: `[target_time-H,target_time)` 안의 모든 관측 종가 중 최저 종가의 가장 최근 확정 시각. H는 A 60분, B 360분입니다.
- 목표 봉 자체와 이후 데이터는 후보에서 제외합니다. episode 상태나 저점 큐 초기화에 의해 검색 범위를 자르지 않습니다.
- t0는 사후 연구 기준점이며 실시간으로 판별한 급등 시작점이 아닙니다.
- raw event는 해당 기준 가격의 **최초 관측 목표 도달**이어야 합니다. 같은 기준 가격으로 이미 목표를 넘은 뒤의 재돌파는 별도 최초 사건으로 만들지 않습니다. MA·거래대금·품질 기준은 가격 사건 발견에 사용하지 않습니다.
- t0부터 H분의 예정 평가 창이 요청 기간 밖으로 나가는 사건은 제외합니다. 구간 내부 누락은 raw에서 지우지 않고 품질 표시로 남깁니다.
- t0부터 +2/+5/+10%의 최초 관측 도달 봉 시작/마감, 소요시간 하한/상한, 관측 품질을 저장합니다. 이는 새로운 매수 조건이 아닙니다.

### ONG 회귀 사례

기존 목표 확인 시각 2026-08-20 22:46 KST를 고정하면 t0는 **22:06 / 82.7**입니다. 과거 구현의 **22:35 / 96.7**은 전체 시간 창 최저 종가가 아니었습니다.

단, 수정한 기준 가격 82.7로는 +10%를 이미 22:26에 관측했습니다. 따라서 22:46을 새로운 최초 사건으로 강제 보존하지 않습니다. 새로 열거한 22:26 목표의 검색 창에서는 **21:30 / 82.3**이 t0입니다. 고정 목표의 t0 수정 검증과, 최초 도달을 다시 탐색한 event 재선정은 다른 작업입니다. 두 비교를 보고서에 분리했습니다.

## 가격 흐름 episode

완성 봉을 시간순으로 보면서 직전에 이미 관측된 고가 대비 종가가 5% 이상 내려오면 구간 경계로 삼습니다. 경계 봉은 이전 구간에 포함하고 다음 봉부터 새 구간입니다. 평가 시간 창의 중첩은 병합 조건으로 사용하지 않습니다.

event의 목표 확인 봉이 속한 가격 구간을 episode로 지정합니다. 실제 관측 시작점·끝점, 저가·고가, 시작/종료 가격, 수익률, 경계 사유·기준 고점·되돌림률, A/B 수와 대표 event ID를 저장합니다. `episode_return`은 시작 가격 대비 종료 종가 변화율이며 high/low 범위는 `episode_range_pct`로 구분합니다. 없는 시작/종료 가격을 다른 시각 가격으로 채우지 않습니다.

전역 t0는 episode 경계를 넘어 과거에 있을 수 있습니다. 이것은 두 정의의 구조적 차이이며 `t0_precedes_episode`로 표시합니다. 구간 내부 데이터 공백이 있으면 관측되지 않은 되돌림을 놓쳤을 가능성도 남습니다.

## 대표 사건과 통계 단위

episode·유형별 **목표 확인 시각이 가장 빠른 event 1개**를 대표로 고릅니다. 이 선택은 품질 필터·대조군 매칭보다 먼저 수행합니다. 첫 대표가 품질 부족이라고 더 나중의 잘 관측된 사건으로 교체하지 않습니다.

원본 event 목록, 대표 여부, 품질 적격 여부, 통계 dataset의 event ID 목록을 별도 저장합니다. raw 수, unique episode 수, 전체 대표 수, 품질 적격 대표 수를 모두 표시합니다. A/B 표본 수를 독립 사건 수처럼 합산하지 않습니다.

## 데이터 품질과 대칭 관측 정책

각 구간에 다음을 저장합니다.

- `expected_minutes`, `observed_minutes`, `coverage_ratio`
- `longest_gap_minutes`, `gap_count`
- 누락 원인은 무체결/수집 누락 중 어느 것인지 판별되지 않았다는 표시

가격·거래대금·봉을 채우지 않습니다. 시작·끝 공백도 길이와 횟수에 포함합니다.

사건과 대조군에 똑같이 **과거 360분, 기준 유동성 구간(t0−360~−240분), 미래 H분**의 최소 coverage를 적용합니다. 이번에는 80%와 100%를 비교하며 최종 연구 기본값을 채택하지 않습니다. 최장 공백은 아직 제한 조건으로 사용하지 않습니다.

매칭용 유동성은 해당 coverage를 통과한 구간의 **관측 분당 평균 거래대금**입니다. 누락을 0으로 간주한 분당 평균이나 전체 구간 총액이 아닙니다. 유동성 1/3~3배, 대조군 재사용 제한, 미래 급등 제외 등의 조건은 유지합니다.

80% 대조군은 `NO_OBSERVED_SURGE_PARTIAL_UNKNOWN_GAPS`로 표시합니다. 이는 관측된 급등이 없다는 의미이며 누락 중 실제 급등하지 않았다고 증명하는 음성 라벨은 아닙니다.

## 특징 품질과 결측

새로운 특징을 추가하지 않았습니다. 기존 정확한 합계·평균 정의를 유지합니다.

- MA·거래대금 합계·고저폭 등은 필요한 창이 완전해야 계산합니다.
- 수익률은 정확한 두 시각의 종가가 있어야 계산합니다.
- 각 특징의 입력 창마다 별도 품질을 기록하며, 스냅샷의 과거 120분 품질도 기록합니다.
- BTC 입력 창도 별도로 기록합니다. 없으면 NULL입니다.
- 분모 0이나 부족한 입력을 0으로 대체하지 않습니다. `null_reasons`에 원인을 남깁니다.

사건/대조군에 동일한 관측 적격 기준을 적용하는 것과, 불완전한 거래대금 합계를 정확한 합계처럼 계산하는 것은 다른 문제입니다. 80% 적격 표본에서도 특정 특징은 NULL일 수 있습니다.

## 최소 표본

각 단일 특징·시점·유형·대조군별로 다음을 출력합니다.

- total_events, valid_event_count, event_valid_rate (0~1 비율)
- total_controls, valid_control_count, control_valid_rate
- paired_valid_count

발생률 차이는 양쪽 특징이 있는 매칭 쌍에서 계산합니다. 사건 유효 수, 대조 유효 수, 유효 쌍 수 중 하나라도 `--min-valid` 미만이면 `INSUFFICIENT_SAMPLE`입니다. 참고 차이는 JSON에 보존하지만 기본 보고서 차이 칸에는 표본 부족으로 표시합니다.

기본값은 20입니다. 이를 넘었다고 유의성·독립성·예측력을 입증한 것은 아닙니다. `SUFFICIENT_FOR_DESCRIPTION`은 기술 통계를 표시할 최소 수가 있다는 의미뿐입니다.
