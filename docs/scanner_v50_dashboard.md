# CHIO COIN SCANNER V5.1 사용 안내

독립 관측 전용 웹 대시보드. Python 3.11 이상과 표준 라이브러리만 사용하며 CHIO BOT과 연결하지 않는다.

## 실행·상태·종료

프로젝트 루트의 BAT를 더블클릭한다. 현재 작업 경로는 `C:\dev\Coin_api`이며, 이전 보고서의 `C:\dev\coin_api-1`은 이 환경에 없다. BAT는 자신의 위치를 사용한다. CMD와 PowerShell에서도 동일하다.

```powershell
cd C:\dev\Coin_api
.\start_coin_api.bat
.\status_coin_api.bat
.\stop_coin_api.bat
```

시작 BAT는 **웹만 열며 스캐너를 자동 시작하지 않는다.** 상단의 **▶ 스캐너 시작**을 눌러 관측을 시작하고 **■ 스캐너 종료**로 정상 저장·종료한다. 웹 종료 버튼은 스캐너만 종료하므로 분석 페이지를 계속 볼 수 있다. 종료 BAT는 스캐너와 웹을 함께 종료한다.
스캐너는 별도 관측 저장소와 기존 관측 엔진을 사용한다. 전체 Windows/NTP 검증을 통과해야 실제 수집을 시작한다. PRECHECK나 프로세스 생성만으로 시작 성공이라고 표시하지 않는다.
관리·감독·수집 단계에서 같은 시계 정책으로 새 검사3회를 수행한다. 준비 확인은 최대75초이며 초과 시 기존 안전 취소/STOP을 사용한다. NTP는 수신1.5초·표본당최대2/전체2재시도·최대8요청/검사전체15초 안에서만 수행한다. 응답 부족은 계속 시작을 차단한다. [실제 시작·종료2회 검증](scanner_start_final_20261026.md).
`SCANNER_CONTROL_FAILED`의 상태 파일 읽기 오류를 실제 API에서 재현해 수정했다. 일시적인 Windows 파일 접근 오류만 짧게 다시 읽고 지속 오류는 차단한다. 연결 카드도 실제 HTTP 장부의 응답200을 확인한다. 요청·시작 단계·예외 종류·Stop 사건은 로컬 `web.log`에 기록한다. [집중 조사·수정 후 실제 관측 검증](scanner_start_diagnosis_20261026.md).
브라우저가 자동으로 열리지 않으면 **http://127.0.0.1:8765** 를 직접 연다.
시계 검증에 실패하면 Scanner **BLOCKED**와 원인을 표시하고 웹은 유지한다. BAT 오류창은 입력을 기다린다.

**웹 RUNNING은 Scanner LIVE 실행을 뜻하지 않는다.** LIVE 카드의 OBSERVING·실제 수집 중을 확인한다.
PRECHECK/STARTING은 수집 준비 상태다. 신호 0건도 정상적인 관측 결과일 수 있다.
스캐너 시작 버튼을 누른 뒤 BAT 창과 브라우저를 닫아도 백그라운드 관측은 계속된다. 웹 종료 버튼 또는 종료 BAT로 끝낸다.
종료 BAT는 이 프로젝트에서 소유한 Scanner의 기존 STOP 이벤트와 웹의 별도 STOP 이벤트만 사용한다.
종료가 확인되지 않으면 BLOCKED를 출력하며 다른 Python/CHIO BOT을 종료하거나 강제 종료하지 않는다.

기본 관측은 수동 종료까지 계속하되 기존 **86400초 / 16000 HTTP** 상한과 모든 fail-safe를 유지한다.
상한·네트워크·시계·자원 조건으로 더 일찍 끝날 수 있다. 자동 재시작은 없다.
**감독하에 사용해야 하며 24시간 무인 운영은 NOT_READY다.**

저장 신호만 볼 때는 LIVE를 시작하지 않는 다음 명령을 사용한다.

```powershell
.\start_coin_api.bat --dashboard-only
# 웹 버튼으로 시작할 관측의 한도를 먼저 고정한다. 아직 수집하지 않는다.
.\start_coin_api.bat --seconds 120 --max-requests 80
# 기존 BAT 직접 관측 시작이 필요할 때만 명시한다.
.\start_coin_api.bat --start-scanner --seconds 120 --max-requests 80
```

`--dashboard-only`는 시계 검증을 통과한 것으로 처리하지 않는다. 기존 기록의 시계 상태를 그대로 표시한다.
이미 열린 웹을 재사용하면 최초 웹 실행 때의 한도가 유지된다. 한도 변경은 종료 BAT 후 다시 시작한다. 브라우저 요청으로 한도·전략을 바꿀 수 없다.
`--check`는 오프라인 Python/import 확인만 수행하고 웹·NTP·LIVE를 시작하지 않는다.
자동 검증용 `--no-browser`는 브라우저 열기만 생략한다. `COIN_API_NO_PAUSE=1`은 BAT 표시 대기만 생략한다.
Python 탐색 순서와 `COIN_API_PYTHON` 지정 방법은 [V4.10 안내](scanner_v410_windows_launcher.md)를 따른다.
API 키나 `.env`, 추가 패키지는 이 관측 진입점에 필요하지 않다.

## 화면의 숫자와 결측

- 감시 종목: 현재 관리 중인 Scanner가 OBSERVING일 때 DB의 실제 범위를 표시한다. 비활성은 0, 근거를 읽지 못하면 UNKNOWN이다. BTC 기준 종목과 거래소·종목 쌍을 구별한다.
- 오늘 신호: KST 탐지일, `source=LIVE`, 별도 관측 DB 기준이다. 원본 연구 보관 신호를 오늘의 신규 신호에 합산하지 않는다.
- 연결: 현재 관측의 마지막 HTTP 장부 결과와 신선도(150초)를 표시한다. 독립 접속 검사를 보내지 않는다. STOPPED/BLOCKED일 때 과거 HTTP 200을 CONNECTED로 표시하지 않는다.
- 시계: 기존 관리 preflight 및 worker CLOCK_CHECK의 상태·나이를 표시한다. 오래된 PASS는 UNKNOWN이다. 웹 조회가 NTP를 추가 호출하거나 차단을 해제하지 않는다.
  V5.2부터 Windows 루트 분산만 큰 경우에는 Windows 동기화 건강 상태와 새로운 두 제공자의 직접 NTP6표본·독립 IP·기존1초 오차/불확실성·일치·신선도를 모두 확인해 교차 검증한다. 통과해도 루트 품질 경고는 유지한다. 응답 누락·실제 오차·동기화 실패는 차단하며 과거 검사 기록을 새 시작에 재사용하지 않는다. [원인·변경·검증](scanner_clock_v52_cross_validation_20261026.md).
- 목록: 원본 연구 보관 / 이번 관측 기록 / 이전 관측을 구별한다. 원천 LIVE/CATCHUP도 별도로 표시한다. 실시간 화면은 최신 200건이며 분석 화면에서 전체 신호를 페이지로 조회할 수 있다. 관측 저장소는 최근 32개 범위다. 현재 원본 DB는 215개이며 과거 문서의 163개와 차이가 작업 시작 전에 존재했다.
- 점수: 기존 V4 엔진은 점수를 정의하지 않아 '미정의'로 표시한다. 변동폭을 점수로 바꾸지 않는다.
- 실시간 화면 후속 지표: 관측 DB의 `live_horizons`를 우선 사용하며 해당 원천 테이블의 PENDING은 웹이 수정하지 않는다. 원본 연구 DB는 5/15/30/60분 지표 테이블이 없으므로 **연속된 실제 저장 분봉 전체가 있을 때만** 종가 변화·고가 MFE·저가 MAE를 화면에서 계산한다. 분석 화면의 별도 평가 캐시는 아래 설명을 따른다. 미래 마감 봉·부분 구간·보간·마지막 가격 채우기는 사용하지 않는다. 원래 L1/L2 연구 평가를 상세 하단에 별도로 유지한다.
- MFE/MAE: 완료된 가장 긴 후속 구간과 그 분 수를 함께 표시한다. 탐지 표시 가격의 근거와 후속 지표 기준 `signal_price`를 구별한다. 체결 수익률이 아니다.
- 차트: 실제 저장 1분봉 종가, 신호 −30분~+60분, 봉 마감 시각 기준이다. 결측 구간은 선을 끊는다. 자료 부족은 PENDING/NO_DATA/UNKNOWN이다.

화면은 5초마다 갱신하며 숨겨진 탭의 폴링은 멈춘다. 선택한 신호는 같은 탭의 새로고침 후 복구한다.
서버 연결이 끊어지면 상태 카드를 UNKNOWN으로 바꾸고 마지막 조회 목록임을 알린다.
브라우저는 시작·정상 종료만 제어한다. 주문·설정·전략 변경은 제공하지 않는다.

## 급등 신호 분석

메뉴는 **실시간 감시**(`/`)와 **급등 신호 분석**(`/analysis`) 두 개다. 분석 화면은 원본 연구와 별도 관측, LIVE와 지연 수집을 구분한다. 저장된 실제 패턴만 표시하며 DIP/REBOUND를 임의로 생성하지 않는다. 현재 V4 패턴은 30분 변동폭 첫 클러스터이며 점수는 미정의다.

- 분석된 신호 수: 적어도 하나의 후속 구간에서 유효한 가격 변화가 완료된 신호 수. 전체 저장 신호 수를 함께 표시한다.
- 30분 상승 비율: 완료된 유효 종가 변화가 **0보다 큰** 신호 / 유효 30분 표본. 0%는 상승으로 세지 않는다.
- 평균 변동률, MFE/MAE: 비교 가능한 **30분 구간** 기준이며 각각의 유효 표본 수를 별도로 표시한다. 실거래 수익률이 아니다.
- 평균 가격 변화: 5/15/30/60분별 실제 유효 값의 산술평균. 시점별 표본이 다를 수 있어 동일 신호 집단의 연속 경로를 의미하지 않는다. 미평가·결측 값은 제외하고 0으로 채우지 않는다.
- 기존 평가의 `signal_time`·`signal_price` 기준을 보존한다. 실제 `detected_at`과 구별하며 지연 수집의 탐지 이후 수익률로 해석하지 않는다. 상세에는 두 시각과 기준 가격을 표시한다.
- 통계는 조회 범위의 전체 신호로 계산하고 목록만 200개씩 페이지를 나눈다. 원본 DB와 기존 카탈로그의 최근 32개 관측 저장소를 조회한다. 원본 연구와 신규 관측을 합친 성능 판정을 하지 않는다.

별도 분석 작업은 **기존 `v42.record_metrics`**를 작은 메모리 복제본에 적용하고 결과만 `data/scanner_dashboard_v50/analysis.db`에 저장한다. 원천 DB·feature·label·기존 COMPLETE를 변경하지 않는다. 기존 worker는 원래대로 원천 `live_horizons`를 평가한다. 분석 페이지는 완료된 저장 값부터 재사용하며 불완전 값은 기존 저장 분봉과 verified 범위로 다시 평가한다. 전체 구간이 없으면 `INSUFFICIENT_DATA`, 아직 시점이 오지 않았으면 `PENDING`이다. 웹 실행 중 약 5초마다 갱신하고 웹 재시작 후에도 같은 저장 자료에서 재개한다. 웹이 꺼져 있으면 별도 평가 작업도 중단된다. 누락 가격을 다운로드하거나 종료된 관측을 자동 재시작하지 않는다.

## 저장·접속 문제

원본 `data/forward_scanner_v4.db`는 immutable 읽기 전용이며 비어 있지 않은 WAL이 있으면 보관 조회를 차단한다.
새 관측 DB는 기존 `data/scanner_v43_live/console_<ID>/`를 사용하고 WAL을 포함한 짧은 읽기 전용 트랜잭션으로 조회한다.
웹 관리 상태와 최대 1MiB×2 로그는 `data/scanner_dashboard_v50/`에 분리한다. 관리 폴더 8MiB/여유 디스크 256MiB 시작 조건, HTTP 동시 처리 8개를 제한한다.
기존 Scanner의 DB 저장·HTTP·로그·자원·1초 시계 기준은 그대로다.

포트 8765가 다른 프로그램에 사용 중이면 `WEB_PORT_OR_START_FAILURE`를 출력하고 새 Scanner 시작도 하지 않는다.
다른 프로그램을 강제 종료하지 않는다. 기존 사용 프로그램을 확인한 후 사용자가 정리하거나 종료한다.
시계 실패는 `status_coin_api.bat`에서 상세 원인을 확인하고 Windows 동기화/NTP 환경을 복구한 후 다시 시작한다.
서비스·방화벽·레지스트리·시각 설정은 BAT가 변경하지 않는다.

서버는 `127.0.0.1`에만 바인딩한다. Host/Origin/Fetch-Metadata 검사, 서버 수명마다 생성하는 인증 토큰, JSON POST의 별도 인증 헤더로 제어 요청을 보호한다. 제어 POST는 정확한 로컬 Origin을 요구한다. 외부 CORS를 허용하지 않으며 CSP와 프레임 차단을 유지한다. GET·상태·분석은 LIVE/NTP/API를 시작하지 않는다.
외부 네트워크 공개, Windows 자동 시작 등록, 주문 기능은 없다.

현재 검증 결과와 한계는 [V5.1 검증 보고서](scanner_v51_validation_20261026.md), 이전 결과는 [V5.0 검증 보고서](scanner_v50_dashboard_validation_20261026.md)에 기록했다.
